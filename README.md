# Proejct1 — sbomfuzz

**sbomfuzz** проводит фаззинг-тестирование компонентов из SBOM с помощью ИИ.
Вы передаёте SBOM в формате CycloneDX, а программа для каждого компонента:

1. скачивает его нужной версии (PyPI, Maven Central или исходники C/C++);
2. отдаёт агенту на Claude, который изучает API компонента и пишет фаззинг-обвязки;
3. запускает обвязки под настоящим фаззером: Atheris (Python), Jazzer (Java), libFuzzer с ASan/UBSan (C/C++);
4. исправляет обвязки, если они не собираются или падают по своей вине;
5. разбирает каждое падение: воспроизводит, читает стек и исходники, отделяет настоящие баги от ошибок обвязки;
6. сохраняет отчёт `report.md` и `report.json`, а также обвязки, входные данные падений и журнал действий агента.

| Экосистема | purl | Фаззер | Откуда берётся код |
|---|---|---|---|
| Python | `pkg:pypi/...` | Atheris | `pip install` нужной версии с зависимостями |
| Java | `pkg:maven/...` | Jazzer | Maven Central: jar, зависимости, sources jar |
| C/C++ | `pkg:github/...`, `pkg:generic/...`, `pkg:conan/...` | libFuzzer + ASan/UBSan | архив по `download_url` или external reference `distribution`, либо `git clone` по `vcs_url` |

Компоненты других экосистем (npm, Go и т. д.) попадают в отчёт со статусом `skipped`.

## Как начать

```bash
git clone https://github.com/godbleeesd/Proejct1.git
cd Proejct1
docker build -t sbomfuzz .
```

Посмотреть, какие компоненты SBOM можно фаззить (API-ключ не нужен):

```bash
docker run --rm -v "$PWD:/data" sbomfuzz list examples/sample-bom.json
```

Запустить фаззинг (нужен ключ Anthropic API):

```bash
docker run --rm -e ANTHROPIC_API_KEY -v "$PWD:/data" sbomfuzz run examples/sample-bom.json --out results --budget-usd 20
```

Отчёт появится в `results/report.md`, артефакты по компонентам — в `results/components/<компонент>/`.

## Основные параметры `run`

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `-o, --out` | `sbomfuzz-results` | куда писать отчёт и артефакты |
| `-e, --ecosystem` | все | только `python`, `java` или `native` (можно повторять) |
| `-c, --component` | все | glob по имени или purl, например `-c 'pkg:pypi/*'` |
| `--limit` | — | фаззить не больше N компонентов |
| `-j, --jobs` | 1 | сколько компонентов обрабатывать параллельно |
| `--fuzz-seconds` | 300 | максимальная длина одного запуска фаззера |
| `--max-turns` | 60 | лимит шагов агента на компонент |
| `--model` | `claude-opus-5-5` | модель Claude |
| `--effort` | `high` | глубина рассуждений: `low` … `max` |
| `--budget-usd` | — | перестать брать новые задачи, когда оценка расходов на API достигнет суммы |
| `--report-language` | `English` | язык текстовых полей отчёта, например `Russian` |
| `--fail-on` | `none` | вернуть код 3, если найден баг этой серьёзности или выше (для CI/CD) |
| `--keep-workdirs` | выкл. | не удалять скачанный код и сборки |

Полный список: `docker run --rm sbomfuzz run --help`.

## Стоимость

Каждый компонент — это отдельная сессия агента на десятки шагов, поэтому расходы растут с числом компонентов.
Реальная стоимость пока не замерялась. Оценка расходов по каждому компоненту и итоговая сумма пишутся в лог и в `report.json`.
Для первых запусков ставьте `--limit` и `--budget-usd`.
Дешевле выйдет с `--model claude-sonnet-5-5` или `--effort medium`, но обвязки получатся хуже.

## Безопасность

При фаззинге выполняется сторонний код: скрипты установки пакетов, системы сборки, сами компоненты.

- Запускайте только в Docker. Внутри контейнера весь недоверенный код работает от отдельного пользователя `fuzzer`
  без доступа к переменным окружения основного процесса, поэтому прочитать API-ключ он не может.
- Содержимое пакетов (README, исходники) может содержать попытки prompt injection. Агенту прямо запрещено
  выполнять инструкции из этих файлов, но ограничения контейнера всё равно нужны.
- Ограничьте ресурсы контейнера, например `--cpus 4 --memory 8g`.
- Сеть нужна для загрузки пакетов и вызовов API. Если требуется изоляция сети, используйте прокси с белым списком.

## Структура проекта

```
sbomfuzz/
  cli.py         команды list и run
  sbom.py        разбор CycloneDX JSON и purl
  fetch.py       загрузка компонентов (pip, Maven, архивы, git)
  agent.py       агент на Claude: инструменты, промпты, цикл работы
  ecosystems.py  запуск Atheris / Jazzer / libFuzzer и разбор их вывода
  sandbox.py     запуск команд от непривилегированного пользователя
  runner.py      обход компонентов, бюджет, сохранение артефактов
  report.py      report.json и report.md
tests/           unit-тесты и интеграционные тесты с настоящими фаззерами
```

## Разработка

Тесты запускаются внутри образа (так же, как в CI):

```bash
docker run --rm -v "$PWD:/src" -w /src --entrypoint sh sbomfuzz -c "pip install -q pytest && pytest -v"
```
